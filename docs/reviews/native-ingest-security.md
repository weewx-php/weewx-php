# Native ingest v1 security review

Date: 2026-09-05. Reviewer: Codex `/root`.
Security-Sensitive: **YES**. Status: **PASS**.

Scope: the native WeeWX receiver, authentication and local admission commands,
shared HTTP adapter, live journal integration, configuration discovery, durable
receipts, retention protection and archive replay. The separate Python collector
runtime and production web-server configuration are outside this review.

## OWASP checks

All ten OWASP Top 10 categories were considered, including the skill's
additional XML, deserialization and XSS checks.

| Category | Result | Evidence |
|---|---|---|
| A01 Access control | PASS | Authenticated collector must match the envelope. Station identities are namespaced; sender IDs are generated by PHP. New stations require local adoption. Token validity and admission are checked in the write transaction. No HTTP administration or cookie authentication. |
| A02 Cryptographic failures | PASS | HTTPS required; only explicitly trusted proxy IPs can attest TLS. Tokens use 32 random bytes, stored as SHA-256 digests and compared with `hash_equals`. Random bearer tokens do not need password-stretching. Rotation immediately invalidates the old digest. |
| A03 Injection | PASS | User values are bound SQL parameters. Measurement identifiers are validated and existing archive identifier quoting remains in use. Driver module names are metadata, never imports, file paths or shell commands. Responses use JSON encoding and `nosniff`; CLI labels reject control characters. |
| A04 Insecure design | PASS | No acceptance before durable commit. Immutable event receipts distinguish retries from new observations. Body/count/field/age bounds, discovery limits, rate limits and configurable receipt capacity bound accepted request work. Repair runs under tick budgets. |
| A05 Misconfiguration | PASS | Reception is disabled by default. Public file works without rewriting or a development router. Errors contain fixed codes or exception class names, not traces, SQL or credentials. No wildcard CORS. Web server owns TLS protocol versions, request read timeouts and outer limits; data must stay outside `public/`. |
| A06 Vulnerable components | PASS | No new production dependencies. Composer audit of locked test/build dependencies returned no advisories or abandoned packages. PHP/SQLite and host patching remain deployment responsibilities. |
| A07 Authentication failures | PASS | Strict token format and digest lookup, peer/global limits plus collector limits across source IPs. Authentication happens before body reading. Disabled collectors and replaced tokens fail; ambiguous header choices fail. |
| A08 Integrity failures | PASS | Bounded JSON decoding, strict envelope/types, duplicate-key detection including escaped names, finite values and immutable receipts. No PHP object deserialization or XML parser. Journal, receipts and repair marks share one SQLite transaction. Checkpoint generation prevents stale progress from clearing newer deliveries. |
| A09 Logging failures | PASS | Request authentication/validation failures log fixed reasons; storage failures log only the exception class. CLI credential/admission changes log IDs and action. Station stored/duplicate counters and per-event ACK reasons expose reception outcomes. No token or request body is logged by the native path. Rate-limited requests do not amplify application logs. |
| A10 SSRF | N/A | Receiver makes no outbound request from submitted input. `driver_module`, IDs and observation names cannot select a URL or executable. |

Tokens are shown only by local creation/rotation commands. Weather data and
receipts use the existing unencrypted SQLite storage model; file access is
controlled by the hosting account. No claim of encrypted database storage is made.

## Findings resolved during implementation

| Severity | Finding | Resolution |
|---|---|---|
| High | A lost HTTP response could cause double contributions, or a premature ACK could lose data. | Transactional event receipts, immutable content checks and `synchronous=FULL`; tests inject a failure on the second receipt and race concurrent retries. |
| High | Collector namespaces or token rotation could be bypassed using an earlier authorization result. | Server-derived station identity and transactional reauthentication; cross-collector and revocation-during-read tests. |
| Medium | Cleanup could remove accepted observations while archive processing was stopped or replay was incomplete. | Durable interval holds and a protected retention cutoff with day/run-up input; stopped-tick and restart tests. |
| Medium | Protecting the entire journal indefinitely would prevent normal cleanup during continuous delivery. | Only the required history constrains the cutoff; expired unrelated observations continue to be pruned. |
| Medium | A fixed receipt ceiling would interrupt sustained collection from several fast stations. | Configurable `max_native_receipts`, advertised capacity and documented 30-day sizing; full-capacity batches roll back while accepted retries remain acknowledgeable. |

No unresolved critical/high findings or deferred findings from this scope.

## Verification

- PHP 8.1: complete PHPUnit suite, **339 tests / 3,616 assertions passed**.
- PHPStan: no errors.
- Project formatter applied to this task's PHP files.
- Full WeeWX conformance suite passed: archive interoperability, accumulation,
  derived values, units, HTTP ingest, native ingest, tick and existing checks.
- Native HTTP test uses original WeeWX 5.5.0 Simulator output and the real PHP
  file in a subdirectory with four PHP workers. Eight concurrent deliveries
  produce one stored observation and seven duplicate ACKs. It verifies CLI
  provisioning/adoption, header alternatives, collector binding, rotation,
  revocation and absence of tokens from application/server logs.
- Replay tests compare records and daily tables with timely input, including
  rain/wind, obsolete extrema, restart checkpoints, concurrent generation
  changes, retention, and existing records on an older interval grid.
- Composer audit of `/opt/build/composer.lock` in `weewx-php-tests`:
  `advisories: []`, `abandoned: []`, exit 0. No production package was added.

The HTTP test simulates a trusted TLS-terminating proxy; it does not test a
public certificate or a particular hosting provider. No USB/serial hardware
compatibility or collector spool durability is claimed by these PHP tests.
